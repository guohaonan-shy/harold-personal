# 02 — Hero boot sequence 编排

**Blocked by**:01(ASCII 头像卡片必须已在位,分镜的最后一拍是它的入场)
**设计冻结**:已冻结(spec [[home-motion-upgrade]] §4 的 boot 分镜时序表,下方已内联)

## 要建什么

访客落地首页时,Hero 像一个终端会话在"启动":徽章行打字 → H1 回显 → 副标题解密 → 描述入场 → ASCII 卡片入场,全程 ≤1.5s,由一个块状光标贯穿交接。每次访问都播(不做首访检测、不设 skip——预算短到不需要)。

分镜(决策载体,来源 spec §4;时刻为目标值,允许 ±10% 内微调但总时长红线 1.5s):

| 时刻 | 事件 |
|---|---|
| 0ms | 全部元素预占位,防布局跳动;背景就位 |
| 0–500ms | 徽章行逐字打出命令(~35ms/字符,**全场唯一逐字打字**) |
| 400ms | H1 两行整行回显(stagger 100ms,opacity + 轻微上移),**不逐字** |
| 600ms | 副标题开始字符解密(复用既有解密动效组件) |
| 700ms | 描述段 fade-in |
| 800ms | ASCII 卡片入场:chrome 头先现,内容随后淡入(此触发槽位后续 WebGL ticket 会挂 settle 动画,本刀只做静态卡片的淡入,但槽位要留成一个明确的触发点) |
| ~1.4s | 完成;徽章行绿点常驻脉冲 |

- **单光标贯穿**:光标在徽章行打完后跳到 H1 尾部闪两次,再交接到副标题解密处。实现精度不达标可降级为「光标只在徽章行」,分镜不变——降级要在交付说明里明说,不静默。
- **移动端**(`pointer: coarse` 判定,不做 UA 嗅探):同一分镜整体压缩至 ~0.8s。
- **reduced-motion**:跳过全部动画,直接呈现最终状态。
- **无 JS**:全部文案与静态头像存在于静态 HTML,动画只是叠加层——禁 JS 页面完整可读。
- **库纪律**:DOM 动效只用既有的 framer-motion,**不引入 GSAP** 或第二套 DOM 动画系统。

## 验收标准

- [ ] 桌面加载:分镜顺序与上表一致,≤1.5s 全部就位,过程无布局跳动(元素不推挤)
- [ ] 单光标交接可见:徽章行 → H1 闪两次 → 副标题(或已声明降级为仅徽章行)
- [ ] 移动端视口:~0.8s 内完成同一编排
- [ ] 系统开启减弱动态效果后加载:无打字、无解密、无入场动画,直接终态
- [ ] 禁用 JS 加载:全部文案与静态 ASCII 头像可见,无空白区域
- [ ] 依赖清单未新增任何 DOM 动画库;构建与 lint 通过
