# 01 — ASCII 生成器 + 静态头像卡片落位

**Blocked by**:无——可立即开工
**设计冻结**:已冻结(spec [[home-motion-upgrade]] §4 的字符场口味 + DESIGN.md 既有终端 chrome 体系,不发明新视觉)

## 要建什么

首页 Hero 的右栏换主角:现在的 Terminal 装饰窗(输出 ACTIVE/CRAFTING 项目状态的那个)退役,取而代之的是一张 **ASCII 头像卡片**——访客看到一张用字符矩阵"画"出来的头像,点按可切换成真实照片,再点按切回。

具体决策(来源:spec §4,本 ticket 自足,不需要回读 spec):

- **构建期生成器**:从头像源图生成 ASCII 字符矩阵。亮度→字符映射,字符集用亮度梯度 ` .:-=+*#%@`(不用片假名、不用纯 0/1)。输出**暗/亮两套**:暗色主题浅色字符,亮色主题深色字符并提高字符密度补偿对比。同时产出一份可直接使用的静态资产(后续移动端与各种降级形态都用它)。运行时只消费预生成产物,不现场重算图像。
- **卡片视觉**:全站统一的终端 chrome(三色圆点 + mono 路径式标题,路径写成指向头像文件的语境),容器圆角与边框沿用既有卡片规范。字符颜色主体走 text 色阶,仅最亮约 10% 的字符用终端绿——"绿色只标记活的东西"。
- **交互(本刀范围)**:点按(click/tap 通用)在 ASCII 与照片间切换。鼠标扰动、hover 解密是后续 WebGL ticket 的活,本刀不做。
- **同刀退役**:上段的圆形照片头像取消(头像角色被卡片接管);Terminal 装饰窗组件删除,其专属翻译词条一并清理——它的状态信息 Upcoming section 已完整承载,不搬家、不做双面卡。
- **布局**:Hero 保持"居中上段(徽章/H1/副标题)+ 下段左文右卡"的既有节奏,本刀落完 Hero 结构即为终态。
- **测试**:建仓库**首个单元测试脚手架**(工具自选,最小化),测的 seam 是生成器的「图片输入 → 字符矩阵输出」函数边界:用仓库内固定小尺寸测试图,断言映射正确性、输出尺寸约束、暗/亮两套的差异。不 mock 自有模块。
