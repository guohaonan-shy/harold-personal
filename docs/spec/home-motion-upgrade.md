# 首页 Hero 与整页动效升级(终端原生动效系统)

## 1 问题

访客打开首页,看到的是一个**静态的终端皮肤**:终端隐喻停在视觉层(圆点 chrome、mono 字体、路径标题),交互和动效没有跟上——各 section 只有各自为政的 fade-up,第一屏没有记忆点。Hero 里普通圆形照片和装饰终端窗两个视觉元素互相争抢注意力,谁都不是主角。站点读起来「像终端」,但不「动得像终端」,高级感的上限被锁在「深色模式的开发者作品集」。

## 2 方案

让动效也说终端的语法,而不是往终端皮肤上贴通用作品集动效:

- **Hero 重构为「工作区」**:上段是 boot sequence 编排(徽章行打字 → H1 回显 → 副标题解密 → 描述入场),下段左文右卡——右侧是新的 signature:一张带三色圆点 chrome 的 **ASCII 头像卡片**,WebGL 字符场渲染,鼠标扰动、hover 解密成真实照片。原圆形照片头像与 Terminal 装饰窗退役。
- **整页统一入场语法**:每个 section 的 prompt line 先打字,内容再跟进——一条规则管全页。
- **WebGL 是实现介质,不是设计语言**:全站唯一的 WebGL 表面是头像字符场;shader 只渲染终端世界存在的东西,不出现通用渐变星云/粒子雾。
- 总入场预算 ≤1.5s,内容是静态 HTML 本体、动画只是叠加层;亮色主题同保真度适配;移动端分层降级;`prefers-reduced-motion` 全线尊重。

## 3 User Stories

1. 作为首次访客,我想要落地后 ≤1.5s 内看到完整可读的首屏,以便不被开场动画挡住信息。
2. 作为访客,我想要 Hero 以终端 boot sequence 的方式逐段「启动」,以便第一眼感知到「这是一个正在运行的终端会话」。
3. 作为回访访客,我想要 boot sequence 短到无需 skip 按钮,以便重复访问不觉得被拖慢。
4. 作为访客,我想要看到一张 ASCII 字符矩阵渲染的头像卡片(带三色圆点 chrome 和路径式标题),以便记住这个站点独有的签名。
5. 作为桌面访客,我想要鼠标划过字符场时字符被轻微扰动、快速轮换并点亮为终端绿,以便获得「这是活的」的交互反馈。
6. 作为桌面访客,我想要 hover 头像卡片时字符层渐隐、真实照片显现,移开后恢复,以便看到真人面孔。
7. 作为桌面访客,我想要一个块状光标从徽章行打字、跳到 H1 回显、再交接到副标题,以便 Hero 读起来像一个 agent 在操作一个会话。
8. 作为移动端访客,我想要 tap 头像在 ASCII 与照片间切换,以便在没有 hover 的设备上获得等价交互。
9. 作为移动端访客,我想要页面不创建 WebGL 上下文、boot 压缩到约 0.8s,以便省电且更快可读。
10. 作为亮色主题用户,我想要所有新动效以同等保真度适配白底(深色字符、无白底 glow),以便亮色主题不是二等公民。
11. 作为开启系统「减弱动态效果」的访客,我想要页面跳过全部动画直接呈现最终状态,以便无障碍地阅读。
12. 作为访客,我想要每个 section 的 prompt 行在进入视口时打字一次、内容随后跟进,以便整页有统一的会话节奏而不是各自为政的入场。
13. 作为无 JS 环境或搜索引擎,我想要全部内容完整存在于静态 HTML、动画只是叠加层,以便 SEO 与可达性不受损。
14. 作为性能敏感的访客,我想要滚动全程没有常驻的全页 shader,以便滚动帧率稳定。
15. 作为站点维护者,我想要 Terminal 装饰窗退役且其项目状态信息由 Upcoming section 继续承载,以便信息不重复、组件不冗余。
16. 作为站点维护者,我想要 DOM 动效唯一归属 Framer Motion、canvas 唯一归属 WebGL 库,以便不出现两套动画系统抢同一批元素。

## 4 实现决策

### Hero 结构(工作区方案)

- 上段维持居中构图:终端徽章 → H1 → 副标题;下段左右分栏:左侧描述文字,右侧 ASCII 头像卡片。
- **退役两个元素**:圆形照片头像(角色被 ASCII 卡片接管)、Terminal 装饰窗组件(其 ACTIVE/CRAFTING 状态输出与 Upcoming section 信息重复,直接删除,不搬家、不做双面卡)。
- ASCII 头像卡片使用全站统一的终端 chrome(三色圆点 + 路径式标题),不发明新卡片头。

### boot 分镜(时序表为决策载体,内联;出处:grill Q11)

| 时刻 | 事件 |
|---|---|
| 0ms | 全部元素预占位,防布局跳动;背景就位 |
| 0–500ms | 徽章行逐字打出命令(全场唯一逐字打字,~35ms/字符) |
| 400ms | H1 两行整行回显(stagger 100ms,opacity + 轻微上移),不逐字 |
| 600ms | 副标题开始字符解密(复用现有解密动效组件) |
| 700ms | 描述段 fade-in |
| 800ms | ASCII 卡片入场:chrome 头先现,字符场从噪声 settle 成头像 |
| ~1.4s | 完成;徽章行绿点常驻脉冲 |

- **单光标贯穿叙事**:一个块状光标在徽章行打完后跳到 H1 尾部闪两次、再交接到副标题解密处。实现精度不达标时降级为「光标只在徽章行」,分镜不变。
- 每次访问都播,不做首访检测、不设 skip(≤1.5s 的预算使两者不必要)。

### ASCII 字符场

- 字符集:亮度梯度 ` .:-=+*#%@`;不用片假名(Matrix 的 IP 气质)、不用纯 0/1(读不出脸)。
- 颜色语义:字符主体走 text 色阶(暗色主题灰白、亮色主题深灰);仅最亮 ~10% 字符与鼠标扰动半径内的字符用终端绿——延续「绿色只标记活的东西」。不做全绿。
- 扰动:鼠标半径内字符快速轮换(与既有解密动效同族的乱码感)+ 轻微斥力;不做夸张物理弹跳。
- 解密:照片常驻底层,字符层盖在上;hover 整卡 → 字符层渐隐;移开恢复。不用 click 切换。
- 字符矩阵**构建期预生成**(亮度→字符映射),运行时字符场消费预生成矩阵;移动端直接使用预生成的静态 ASCII 图资产。

### 库归属与技术边界

- DOM 动效唯一归 Framer Motion;**不引入 GSAP**(避免两套 DOM 动画系统)。
- canvas/WebGL 归 three.js 或 OGL(取更轻者),全站仅头像字符场一个 WebGL 表面。
- 不做全页 CRT 氛围 shader 层(滚动性能风险 + 亮色主题收益趋零)。

### 整页 section 入场语法

- 每个 section 的 prompt line 进入视口时,命令部分逐字打出(~30ms/字符),仅播一次(回滚再进不重播)。
- prompt 完成后,该 section 内容按既有入场参数(0.6s easeOut,opacity + y 位移)stagger 跟进——既有动效保留,只是触发时机被 prompt 链住。既有打字机标题组件成为这套语法的载体。
- 滚动进度指示**不做**(导航是页面级 tab 而非 section 锚点,且单页仅 6 个 section,导航价值趋零)。

### 主题与降级链

- 亮色主题同保真度:字符场用深色字符 + 提高密度补偿对比;所有 glow 类效果换成锐利对比/字重变化,不做白底发光。
- 移动端(`pointer: coarse` 判定,不做 UA 嗅探):不创建 WebGL 上下文,头像为静态预生成 ASCII 图,tap 切换 ASCII/照片;boot 压缩至 ~0.8s;hover 触发的效果改为进入视口触发一次。
- `prefers-reduced-motion`:跳过全部动画,直接呈现最终状态。
- 无 JS / WebGL 不可用:内容完整存在于静态 HTML;头像回退到静态 ASCII 图(与移动端同资产)。

## 5 测试决策

### 仪器矩阵

| 变的是什么 | 仪器 | 本次 |
|---|---|---|
| 纯逻辑 / 数据转换 | TDD 单元 | **涉及**:构建期 ASCII 矩阵生成——亮度→字符映射的正确性、输出矩阵尺寸约束、暗/亮两套输出的字符密度差异 |
| API 契约 | TDD API 测试 | 不涉及(纯静态导出,无 API) |
| DB schema / 迁移 | 真 DB 测试 | 不涉及(无数据库) |
| LLM 输出质量 | eval | 不涉及(**无 prompt/eval 变动**) |
| 视觉正确性 | 截图对比 | **涉及**:首页 Hero 最终态,暗/亮双主题 × 桌面/移动双视口,共 4 张基准 |
| 端到端用户流程 | 浏览器测试 | **涉及**:boot 完成后内容可读、reduced-motion 直达最终态、移动端 tap 切换、prompt 只播一次 |

### seam

优先复用、越少越好,本次共两个:

1. **主 seam(复用):浏览器中渲染完成的首页**。视觉截图对比和全部 E2E 断言都测在这一层——只观察渲染结果与交互响应,不伸手进组件内部。
2. **新增 seam(唯一新增):ASCII 生成器的「图片输入 → 字符矩阵输出」函数边界**。单元测试测在这一层,输入固定的小尺寸测试图,断言输出矩阵的映射与尺寸。

字符场的 WebGL 运行时内部**不设 seam**——canvas 内部状态无法黑盒断言,其行为一律通过 seam 1 的截图与交互验证。

### 增量功能测试(全部落在首页)

1. **boot 完成性**——前置:桌面视口,动画开启;步骤:加载首页并计时;期望:≤1.5s 内徽章行、H1、副标题、描述、ASCII 卡片全部可见且不再变化,过程无布局跳动;覆盖:US 1/2/3。
2. **头像解密**——前置:桌面视口;步骤:hover 头像卡片,再移开;期望:hover 时照片显现,移开后字符场恢复;覆盖:US 6。
3. **reduced-motion**——前置:系统开启减弱动态效果;步骤:加载首页;期望:无打字、无解密、无字符 settle,直接呈现最终状态;覆盖:US 11。
4. **移动端档位**——前置:`pointer: coarse` 视口;步骤:加载首页,tap 头像;期望:页面未创建 WebGL 上下文,头像为静态 ASCII 图,tap 在 ASCII/照片间切换;覆盖:US 8/9。
5. **section 语法**——前置:桌面视口;步骤:逐个滚动到各 section,回滚后再进入;期望:每个 prompt 打字一次且不重播,内容在 prompt 完成后入场;覆盖:US 12。
6. **亮色主题同保真**——前置:切换到亮色主题;步骤:加载首页走完 boot;期望:字符场为深色字符,无白底 glow,boot 编排与暗色主题同样在场;覆盖:US 10。
7. **无 JS 降级**——前置:禁用 JS;步骤:加载首页;期望:全部文案与静态 ASCII 头像可见,无空白区域;覆盖:US 13。

### mock 边界

- 单元测试中唯一的系统边界是**图片文件输入**:用仓库内固定的小尺寸测试图,不 mock 自己的映射逻辑。
- 不 mock 任何自有模块;E2E 与截图层不 mock(测的就是真实渲染)。

### 既有同类测试的先例

项目目前**没有任何自动化测试先例**——单元与 E2E 均为首建,测试脚手架选型是开工凭据(ticket)阶段的决策,不在本 spec 内定。截图对比沿用 design-workflow 插件既有的截图流程。
